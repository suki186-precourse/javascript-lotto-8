## 🪐 [Precourse 3주차] 로또

간단한 로또 발매기를 구현한다.

> indent(인덴트, 들여쓰기) depth는 최대 2까지.
> 3항 연산자 쓰지 않기.
> 함수는 한 가지 일만 하도록 최대한 작게.

---

### ✨ 구현할 기능 목록

**🔹 기본 기능**

1. 로또 구매 금액 처리

- [x] 1,000원 단위 입력 받기
- [x] 발행 수량 계산: 금액 / 1000
- [x] 발행 수량 출력

2. 로또 발행

- [x] 1~45 사이 중복 없는 랜덤 값 6개 생성
- [x] 오름차순 정렬
- [x] 로또 발행 결과 출력(발행 수량만큼)

3. 당첨 번호 처리

- [x] 당첨 번호 6개 입력 받기
- [x] 보너스 번호 1개 입력 받기
- [x] 각각 숫자배열, 숫자로 변환 후 저장

4. 당첨 확인 및 출력

- [x] 로또와 당첨 번호를 비교해 맞춘 번호 개수를 계산
- [x] 등수별 당첨 횟수 카운트
- [x] 당첨 통계 결과 출력

5. 수익률 계산

- [x] 총 당첨 금액 계산
- [x] 구입 금액 대비 수익률 계산 및 소수점 둘째자리에서 반올림
- [x] 총 수익률 출력

**🔹 예외 처리**

1. 로또 구입 금액 유효성 검증

- [x] 1,000원 단위가 아닌 경우
- [x] 1,000원 미만의 값을 입력한 경우
- [x] 정수가 아닌 값을 입력한 경우(공백, 빈 값 포함)

2. 당첨 번호 유효성 검증

- [x] 1~45 범위가 아닌 숫자를 입력한 경우
- [x] 정수가 아닌 값을 입력한 경우(공백, 빈 값 포함)
- [x] 중복된 번호를 입력한 경우
- [x] 입력한 숫자가 6개가 아닌 경우
- [x] 쉼표(,) 외 다른 구분자를 사용한 경우

3. 보너스 번호 유효성 검증

- [x] 1~45 범위가 아닌 숫자를 입력한 경우
- [x] 입력한 숫자가 1개가 아닌 경우
- [x] 정수가 아닌 값을 입력한 경우(공백, 빈 값 포함)
- [x] 당첨 번호와 중복된 번호를 입력한 경우

**🔹 테스트 코드**

- [x] Jest를 이용하여 정리한 기능 목록이 정상적으로 작동하는지 테스트

### 📁 src 디렉토리 구조

```bash
src/
├── App.js
├── index.js
│
├── controller/
│   └── LottoController.js  # 전체 흐름 제어
│
├── domain/
│   ├── Lotto.js            # 단일 로또 객체
│   └── LottoGame.js        # 비즈니스 로직
│
├── view/
│   ├── InputView.js        # 사용자 입력
│   └── OutputView.js       # 결과 출력
│
├── utils/
│   ├── lottoUtils.js       # 번호 비교, 정렬, 매칭
│   ├── validators.js       # 입력값 검증
│   ├── calculator.js       # 수익률, 당첨금 계산
│   └── parser.js           # 자료형 변환
│
└── constants/
    ├── message.js          # 입출력 관련 상수
    └── lotto.js            # 로또 관련 상수
```

### 💡 트러블 슈팅, 고민했던 부분

- 다음 두가지 경우의 수 중에 고민을 많이 했는데, 결국 1번을 선택했습니다. 혹시 다른 더 좋은 방법이 있다면 코멘트 달아주시면 감사하겠습니다.

  **1. `parser.js` 작성**

  - 방식: `validators.js`는 유효성 검증만 담당하고, `parser.js`는 파싱만 담당.
  - 장점: SRP을 완벽하게 지킴. 각 파일의 역할이 명확하게 분리.
  - 단점: `split().map()` 파싱이 2번 실행되어 비효율이 발생.
    - 1번째: `validators.js` (범위, 중복 검사를 위해)
    - 2번째: `LottoController.js`가 `parser.js`를 호출할 때 (파싱된 값을 사용하기 위해)

  **2. `parser.js` 제거**

  - 방식: `validators.js`가 유효성 검증을 수행하고, 검증이 통과되면 파싱된 결과를 직접 반환.
  - 장점: `split().map()` 파싱이 1번만 실행. `validators.js`가 검증을 위해 파싱 결과를 재사용하므로 효율적.
  - 단점: SRP을 완벽히 지키지 못함. `validators.js`가 '검증'과 '파싱'이라는 두 가지 책임을 갖게 됨.

- `@params`, `Object.freeze`, `Controller` 등 이전까지 사용하지 않았던 기능, 함수를 써보도록 노력했다.
  확실히 다른 분들과 코드리뷰를 하는게 몰랐던 함수들도 알게되고, 더 나은 코드를 작성하는 데 도움이 되는 것 같다.
